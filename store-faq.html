lumentoSTORE questions

Setting up, what STORE puts on your NAS, and importing a camera card, in plain words.

Setting up

Getting STORE running on your NAS.

Passwords, the admin page, your archive folder and what STORE needs from your NAS.

The admin page won't let me set a password, or says it's already claimed.

The first password set in the five minutes after STORE starts owns it. It needs at least 15 characters and mustn't be an obvious one. Setting the first password works only from a device on your home network.

If the five minutes passed and nobody claimed it, turn lumento STORE off and on again in App Central for a fresh five minutes. If the page says "already claimed", someone set the password. If that was you, log in.

The browser warns about the certificate. Is it safe?

Yes, that's expected. STORE makes its own security certificate, which your browser doesn't know, so it warns. The connection is still encrypted.

Your iPhone doesn't rely on the browser's check. It remembers the certificate's fingerprint when you pair and refuses to talk to anything else. The certificate effectively never expires and is only remade if its files go missing, in which case phones must pair again.

Where is the admin page, and why port 20903?

Open https://<your NAS>:20903/ in a browser, or open it from the lumento STORE icon on the ADM desktop. The page has three tabs: Settings, Card import and Logs. The number is just the port STORE listens on.

I forgot the admin password.

There's no reset button, on purpose. Uninstall lumento STORE, install it again, and set a new password within five minutes.

You'll lose STORE's settings, the password, your destinations, your phone pairings and its security certificate, so phones pair again. You keep your photos and the marker file in your archive. If you pick the same archive folder again, STORE recognises the marker and carries on with that archive. Phones then announce everything again, but files already at the right name with identical contents are adopted, not stored twice.

Files you renamed or moved, or a changed naming style, would be written again.

Why does STORE ask for a folder? Can I change it later?

STORE writes only inside the folder you choose and leaves the rest of the NAS alone. It must be a folder inside a volume (for example /volume1/Photos), not the bare volume.

You can change it later on the admin page ("Change folder"), but nothing already archived is moved. STORE treats the new folder as a new archive: photos loaded before stop counting as loaded, and phones send everything once again (anything already there is skipped). The page doesn't warn you when you change it, and changing back later doesn't bring the old archive's records back.

Which NAS works, and why only Asustor? Does it need Docker?

Today STORE is an App Central package for Asustor NAS (ADM 5.1 or later; x86-64 and ARM). It's one package and needs no Docker, database or other app.

On any other NAS that serves WebDAV over HTTPS, LOAD's Generic mode is the way in.

What NAS permissions does STORE need?

STORE runs as its own system account (lumentostore, not root), which is in ADM's administrators group, so it can reach any folder that group can write. It only writes inside the archive folder you choose.

The admin page's folder browser lists folders under your volumes to whoever has STORE's password. Files are saved readable by others (0644, folders 0755), so ADM share permissions decide who can see them.

What STORE puts on your NAS

What you’ll find in your archive folder.

The files STORE keeps, how it names them, and what you can safely move around.

What are .lumento-archive-id.json, .staging, .chunks and .part? Can I delete them?

Leave them alone. STORE looks after them.

  • .lumento-archive-id.json is a small marker beside _lumento that tells STORE which archive this is. Don't delete it: STORE would treat the archive as new and phones would send everything again.
  • .staging and .chunks (hidden, inside _lumento) hold files still arriving. STORE cleans them up itself. A .part file name appears in chunk storage under .chunks.
  • STORE never creates .DS_Store. macOS does.

How are files named, and can I change the date style or keep original names?

By default a file is named like 2026.08.30 13.46.33.123.HEIC and filed in _lumento/2026.08/.

On the admin page, Filename rules lets you choose the date style (2026.08.30, 2026-08-30, 20260830 or original filename), the joiner (space or underscore), seconds or milliseconds, a person label (off, after the time, before the date) and whether months sit in year folders.

A change affects only new files. STORE never renames old ones, so two styles can sit side by side. That's intended.

What's the “e” at the end of a time like …000e.MOV? Why are some files in the wrong month?

The "e" means the date is an estimate: STORE couldn't read a date inside the file. That happens for files with no readable date, such as PNG screenshots, videos with no date or a UTC-only date, and files from a camera card with no date inside.

For those, STORE uses the file's own date, which can be wrong, and files are filed in the month of the name. Photos, iPhone videos and the other formats STORE can read are dated from inside the file, with no "e".

Some files end in (2), or two look identical. Are they duplicates?

No. A " (2)" means two different files would have had the same name (the same moment, or names that differ only by capitals), so the second got a number.

Files that are byte for byte identical aren't stored twice, so identical copies don't pile up.

I moved or deleted photos inside _lumento. Will LOAD send them again?

No. STORE never looks at the archive after writing a file, so it doesn't notice, and LOAD still counts them as archived. Reorganise the folders freely.

Deleting the marker file is the exception: STORE then sees a new archive and phones send everything again.

Phones and pairing

Connecting and disconnecting phones.

How the pairing code works, how to unpair a phone, and what a new phone sends.

What does the pairing code do, why is it one try, and how long do lockouts last?

Start pairing on the admin page ("Generate pairing code"). The code is six digits, lasts five minutes and allows one try. A new code cancels the old one. It works only on your home network.

Repeated wrong tries from one address (25 in a day) lock that address out for 24 hours, or 7 days if it repeats. Many addresses at once pause pairing across the whole NAS until it clears itself after six hours. You can press "Clear" on the admin page.

How do I unpair a phone?

On the admin page, go to Paired devices and press "Unpair". The phone stops being able to send photos at once and can only return by pairing with a new code. Photos it already sent stay where they are.

On the phone, "Forget lumento STORE" does the same from its side.

I reinstalled LOAD or have a new iPhone. Will everything upload again?

No. LOAD checks everything on the phone once, but the NAS skips what it already holds, by content. Nothing is stored twice. More in the LOAD FAQ.

When something goes wrong

Full disks, updates and interrupted imports.

What STORE does when space runs out, after an update, and when a card import ends early.

The NAS ran out of space. Did I lose photos?

No. STORE refuses new uploads while free space is below its cushion (500 MiB by default), tells the phone to wait, keeps everything already verified and carries on once there's room.

The admin page's System section shows free space and says "Phones are waiting for space."

Will updating STORE log out my phone or lose settings?

No. An update keeps your settings, password, destinations and pairings, and phones stay paired. STORE saves its database and its certificate before the update and restores them after.

If an update stops partway, STORE won't start until that saved copy is restored, and it tries again at each start.

Is my archive OK after an import ended “partial”, or the card was pulled?

Yes. Files that were archived stay archived: a file only counts once it's fully written and verified. A partial upload is cleared when the run ends.

Run the import again with the card, and files already archived are skipped.

Staying private

What leaves your network, and what doesn’t.

STORE sends nothing out by itself, and your phone can reach it from away only if you set that up.

Does anything leave my network? Can I use LOAD away from home?

STORE sends nothing out by itself: no update checks, no telemetry, no cloud, and the admin page loads no outside assets. LOAD talks to your NAS and nowhere else, over an encrypted connection to the NAS's port 20903.

What crosses that link on a Load: the files, their fingerprints, and each file's name, size and capture time (plus the destination and the person label). The NAS replies with what it did, including where each file was filed. Pairing a phone and claiming STORE work only from your home network.

Away from home. Yes, once you set it up. STORE's admin page has an "Outside access" section that holds one address: a DDNS name or a host name you own, with a port if your router maps a different outside port to 20903.

If your Asustor has a Cloud ID, the page suggests its <id>.myasustor.com name, which works once ADM's DDNS is on (ADM > Services > EZ-Connect > DDNS). "Use this" fills the field, and nothing is saved until you save it.

Your paired phone learns the address from STORE over its encrypted connection, looks for STORE on your home network first, and uses the outside address when it isn't there. It checks the same certificate either way, so something else answering at that address can't pass for your NAS.

You make the address reachable yourself: forward your router's port 20903 to the NAS, or use a VPN. Don't use a proxy or tunnel program on another computer at home: STORE would take its visitors for home devices.

Forwarding port 20903 lets your phone reach STORE from away, and nothing else. The admin page, card import included, opens only from your home network.

In LOAD's Settings, "Load over cellular" is off at first: until you turn it on, LOAD transfers only on Wi-Fi, and a Personal Hotspot counts as cellular. If no outside address is set, LOAD says "lumento STORE can be reached only at home. Its administrator can set an outside address."

Importing a camera card

Getting photos off a card and onto your NAS.

It happens in your browser, on STORE's admin page, in the Card import tab: the card stays plugged into your computer, and the page reads it and sends it to your NAS.

The browser asked “Upload N files to this site?” Is my card going to the internet?

No. That's your browser's standard question for any folder you choose, and the "site" is your NAS. Say yes: that starts the import. The page sends the files to STORE over your network.

Why does it “read” the whole card first, then read each file twice?

Each file is read once to take its fingerprint (SHA-256) and again as it's sent, so STORE can check what arrived against a fingerprint it didn't make. Reading and sending run at the same time.

Keep the card in until the import finishes.

Which browsers work?

A current Chrome, Edge, Firefox or Safari. If the page says it needs JavaScript, turn JavaScript on or switch to one of these.

Can I drag the card folder instead of picking it?

No. Choose the card with the "Choose the card and start…" button (pick its top level), and that starts the import.

I closed the tab, my Mac slept, STORE restarted, or my login expired. Is anything lost?

Nothing already archived is lost.

  • Closed tab: the import stops (your browser warns first). Archived files stay, and a re-run skips them.
  • Mac slept: after a short sleep the page retries and carries on. For a long sleep, keep the Mac awake.
  • STORE restarted or updated: the page says so. Import the card again.
  • Login expired: a small login box appears. Log in and it carries on.

The card was pulled. Why 18 minutes, and what's “Finish without the card”?

The page waits up to 18 minutes for you to put the card back, and carries on by itself when you do. If it isn't back in time, the import finishes without the files it hasn't sent, and says it's partial.

Pulling the card again uses what's left of the 18 minutes. The full time comes back only once a file has landed since you put it back. "Finish without the card" ends the import now, the same way.

Either way, run the import again with the card to send the rest. What's archived is skipped.

What does “only partial” or “we got 22 of 23” mean? Is it safe to wipe the card?

  • "Only partial": the card stopped being readable partway. Run the import again to send the rest.
  • "We got 22 of 23": one file couldn't be read. Copy it yourself.
  • When everything's in, the page says "Import finished. Every file on this card is archived and checksum verified."

If it says it "cannot confirm that every file on this card is archived", check the card against what's archived before you erase anything. STORE never says it's "safe to format". That's your decision.

I imported the same card twice, or two cards with the same file names (DSC0001). Duplicates?

No. STORE recognises files by content, across the whole archive, so a file it already holds isn't sent or stored again ("Already in the archive").

Files are named by when they were taken, not by the camera's number, so two cards with the same names don't collide. The rare same-moment pair gets a "(2)". For six months (a setting) the page also hints "You have imported this file before."

The report says 23 on the card, 22 archived, 1 already there and housekeeping files skipped. Why does a .cube or .CPI file import?

The page doesn't filter by file type. It skips only computer housekeeping files (such as .DS_Store and Thumbs.db) and a few camera index files, by exact name, and sends everything else, including unusual files. Those are named from the file's date with an "e" and filed by month.

My card reader reset dates to today, or the camera clock was off. Which date is used?

Photos and clips with a readable date are unaffected: the date comes from inside the file.

Files with no date inside (such as .cube or loose index files) use the card's file date, which may be wrong, and get an "e". If the camera's own clock was wrong, the name carries that wrong time.

What do Destination, Folder and Label mean? Can I preview the names?

  • Destination: where this card's files go (by default, filed by month).
  • Folder (optional): puts the whole card in one folder inside the destination, instead of by month, for this import only.
  • Label (optional): a name sent with the card. It shows in file names only if STORE's person label is turned on.

These are fixed once an import starts. There's no preview: STORE names each file as it archives it, and the real names appear in the report.

Why did the report shrink to “cannot confirm that every file is archived” later?

The full report is kept while the import is in use. After 30 minutes with nobody opening it, STORE rebuilds it from its own record. That record lists the archived files and where they are, but not each file's path on the card, so it can't prove every file was archived.

Check the card against the archive before erasing it.

The page says the NAS asked for a pause, or froze for a few seconds. Is the NAS busy because my phone is loading?

Possibly. STORE shares its upload capacity. The card import keeps to an equal share and pauses when STORE is busy; the page says STORE asked lumento to pause and that the import resumes by itself.

A phone Load is never held back by a card import: the card waits. A big clip can also pause for a moment while it's fingerprinted. Nothing is lost.

How fast should an import be?

It depends on your card, reader, network and NAS. Reading the card and sending run together, and a big clip waits to be fingerprinted before it goes. No speed is promised.

Why do the RAW and JPEG share a name, and why do they count as one?

A RAW and a JPEG with the same name in the same folder travel as one photo, so they get the same time-based name with their own endings. The report counts files, so the two show as two files.

What about AVCHD and Sony XAVC cards?

AVCHD camcorder cards import. Each clip (.MTS or .M2TS) arrives as a video, named from the date and time the camcorder recorded inside it, as its own clock showed. A clip with no date STORE can read is named from its date on the card instead, with an "e".

STORE doesn't treat AVCHD's folders as one recording, so the card's other files (its index, playlist and clip-information files) are archived too, as ordinary files named from their card date with an "e". Nothing on the card is left behind.

Sony XAVC cards: each clip is kept together as one item (the video, its XML description, its thumbnail and its proxy) and dated from the clip's XML. A few of the camera's own card index files are skipped, because they describe no single clip and the camera rebuilds them.

A file is marked “unreadable”.

The browser couldn't read that file from the card. It fails alone and the rest goes through. It's listed under "These need you" with "This file could not be read from the card", and in the report as "Not read from the card". Keep the card and copy the file yourself.

The Card import tab says “Set an archive location in Settings first”.

STORE doesn't know where to put the card's files yet. Choose the archive folder in Settings, come back, and the Start button works. The page re-checks when you return to it.

"Card import is turned off on this NAS" means the admin switched card import off in Settings.

Who can import a card?

Anyone logged in to STORE's admin page with the admin password. A paired phone, or a command-line app token, can't import a card.

Can I undo an import?

No. Cancel stops the run, and files already archived stay archived. STORE never deletes what it has archived.

Does importing change or delete anything on my card?

No. The page only reads the card. It has no way to write, rename or delete files on it.
