Set up your NAS for Generic mode.

Generic mode lets lumento LOAD write to your NAS over WebDAV, with no lumento STORE installed. This page walks you through it, one step at a time.

Jump to: Asustor · Synology · QNAP · Another NAS · Connect from LOAD · The certificate prompt · Troubleshooting

What you need

Three things.
About 10 minutes.

  • A NAS that serves WebDAV over HTTPS. Asustor, Synology and QNAP all do. So do most others.
  • A computer on the same network, to set the NAS up from. You'll use its browser to open the NAS's settings.
  • About 10 minutes.

What's WebDAV?

It's a way for an app to put files on your NAS over the web. It's built into the NAS, so on most units you turn it on rather than install it. On some, like Synology, it's a small package from the NAS's own app store. HTTPS is the encrypted version, so your password never crosses your network in the clear.

Before you start

What LOAD does on your NAS, and what it never does.

You're letting an app write to your NAS. Here's exactly what it does there.

Where it works

The address you enter is the folder LOAD works in. Inside it, LOAD makes one folder, _lumento, and puts your photos in month folders like _lumento/2026.11. Beside it, it keeps two small hidden items: .lumento-generic-archive.json, and a .lumento-generic folder holding a copy of LOAD's list of what it sent, so a reinstalled app still knows. Nothing else.

When you connect, LOAD also writes two tiny test files into _lumento and removes them again.

How a file lands

Each file is uploaded under a temporary .part name, then renamed to its final name in one step, with the "don't overwrite" flag. An existing file is never replaced, and a half-finished upload never shows up under a real name.

What it deletes

LOAD never deletes a photo once it has passed its check. It deletes only:

  • its own leftover .part files from a failed upload,
  • its own connection-test files, and
  • in the rare case that a file it has just written fails its check, that one file, and only if the NAS says nothing has touched it since. LOAD then uploads it again.

Your password

LOAD only connects over https://. It refuses http://, because your password would cross your network in clear. The password is kept in your iPhone's Keychain.

What Generic mode can't do. It checks each file's size and, once the file lands, reads back a few random blocks. It doesn't verify every byte the way STORE does. See the comparison table for the rest.

The setup

Pick your NAS.

Every NAS needs the same four things, in the same order: turn on WebDAV over HTTPS and note the port; make a folder just for your photos; make a user that can use only that folder; check there's no separate WebDAV permission in the way.

Why a user just for LOAD? It's optional, but we recommend it. Then the NAS itself keeps LOAD out of everything else, whatever LOAD does.

Jump to: Asustor · Synology · QNAP · Another NAS

Asustor · ADM

Asustor

Menu names are shown in [brackets], as ADM writes them.

1. Turn on WebDAV with HTTPS

In ADM, open [Services] → [WebDAV]. Tick [Enable secured WebDAV service (SSL)], then click [Apply]. The default HTTPS port is 9802 (the plain HTTP port, 9800, is the one LOAD refuses). Write down the port if you've changed it.

2. Make a shared folder for your photos

Open [Access Control] → [Shared Folders] and add a new shared folder, for example phone-photos. ADM's help page doesn't name the button, so look for the one that adds a folder.

3. Make a user that can use only that folder

Open [Access Control] → [Local Users] and add a user, for example load, with a strong password. Then give it rights to your photo folder: [Read & Write].

Watch the default folders. ADM makes a shared folder called public, and by default all users can open it. It also makes a personal folder for each user. In [Shared Folders], set the new user to [Deny Access] on public and on every other folder, so it can reach only your photo folder.

4. Check for a separate WebDAV permission

There isn't one. ADM says WebDAV uses the login account's shared-folder rights, and the levels are [Read & Write], [Read Only] and [Deny Access]. So step 3 is all you need.

Your address will look like https://nas.local:9802/phone-photos/. Next, connect from LOAD.

Synology · DSM

Synology

Menu names are shown in bold, as DSM writes them.

1. Install WebDAV Server and turn on HTTPS

Sign in to DSM as an administrator. Open Package Center and install WebDAV Server. Open it, go to Settings > HTTP/HTTPS, select Enable HTTPS and click Apply. The default HTTPS port is 5006. You can change it, so note the one you use.

Leave Enable Anonymous WebDAV off. LOAD signs in with a user.

2. Make a shared folder for your photos

Go to Control Panel > Shared Folder and click Create > Create Shared Folder. Give it a name such as phone-photos and pick a storage location.

3. Make a user that can use only that folder

Go to Control Panel > User & Group > User and click Create. Enter a name such as load and a strong password.

The wizard has a Join groups page and an Assign shared folders permissions page. A group the user joins can bring folder rights with it, and when a user's rights and a group's rights disagree, No access wins. So on the permissions page, give the new user Read/Write on your photo folder and No access on every other shared folder, such as the default photo, video, music and homes folders. The Preview column shows what the user can really reach.

4. Check for a separate WebDAV permission

The same wizard has an Assign application permissions page, which controls which services the user can use. Deny beats Allow there, so don't deny this user WebDAV.

Your address will look like https://nas.local:5006/phone-photos/. Next, connect from LOAD.

QNAP · QTS

QNAP

Menu names are shown in bold, as QTS writes them.

1. Turn on WebDAV with HTTPS

Log on to QTS as an administrator. Go to Control Panel > Network & File Services > Win/MAC/NFS/WebDAV > WebDAV and select Enable WebDAV. To pick the ports yourself, choose Dedicated port number and set the HTTPS port number. Click Apply.

Write down the HTTPS port number you chose. QNAP's page doesn't name a default, so use the number your NAS shows.

2. Make a shared folder for your photos

Open File Station, use the create button on the menu bar, and choose Shared Folder. Give it a Folder Name such as phone-photos and pick a Disk Volume.

3. Make a user that can use only that folder

Go to Control Panel > Privilege > Users, click Create > Create a User and enter a username such as load and a strong password. Under Shared Folder Permission, click Edit and give the user Read/Write on your photo folder.

Watch the default folders. QTS makes Multimedia, Public and Web folders. Any user account can use Public, with Read Only by default. Set the new user to Deny on those folders and on any other folder you don't want LOAD near.

The same window lets you edit Application Privilege. QNAP recommends denying a user the apps and network services it doesn't need. Do that, but leave WebDAV allowed.

4. Choose the WebDAV permission type

Back on the WebDAV page, QNAP offers two options: Shared folder permission and WebDAV permission. QNAP's page doesn't say what they mean. Choose Shared folder permission, so the folder rights from step 3 are the ones that count. If LOAD's connection test then says the account is refused, this is the first thing to check.

Your address will look like https://nas.local:<HTTPS port>/phone-photos/. Next, connect from LOAD.

Any other NAS

Another NAS

Menus differ, but the four steps are the same. Look in your NAS's own help for the words below.

1. Turn on WebDAV with HTTPS

Look for a WebDAV setting, in the file services or sharing section, and switch on the secure (HTTPS or SSL) version. Note the HTTPS port. It isn't 443 on every NAS.

2. Make a shared folder for your photos

Make a new shared folder only for photos, such as phone-photos.

3. Make a user that can use only that folder

Make a new user, with a strong password, that can read and write that folder and nothing else. Check any default shared folders, such as public, and deny the new user access to them.

4. Check for a separate WebDAV permission

Some NAS units also decide which users may use WebDAV at all, apart from folder rights. If yours does, allow the new user.

Then connect from LOAD. The connection test checks everything LOAD needs and tells you what's missing.

Connect from LOAD

Three boxes and a test.

In LOAD, choose Connect over WebDAV. On the Connect your NAS screen, fill in:

  • Address: https://<your NAS's address>:<HTTPS port>/<shared folder>/. The address can be a name like nas.local or an IP address like 192.168.1.20.
  • Username: the user you made.
  • Password: that user's password.

Examples

  • Asustor: https://nas.local:9802/phone-photos/
  • Synology: https://nas.local:5006/phone-photos/
  • QNAP: https://nas.local:<HTTPS port>/phone-photos/

The folder at the end of the address is where LOAD works, so a deeper folder such as …/phone-photos/iphone/ works too.

The connection test

Tap Connect. The button reads Testing… while LOAD runs its test on your NAS. It checks that the NAS speaks WebDAV, that your folder can be read, and that LOAD can write a file, rename it into place, refuse to overwrite, report a size and read part of a file. It then removes its test files. Each step shows as it passes. When they all pass, you'll see Connected.

If it says your NAS uses HTTP/2: iPhones can't upload to an HTTP/2 server in the background, so LOAD copies while it's open. Keep LOAD open for the Load.

The certificate prompt

"Check this certificate."

You'll probably see this once. It's the right thing to see.

Most home NAS units make their own HTTPS certificate, so no outside authority vouches for it. The first time you connect, LOAD shows you the certificate's SHA-256 fingerprint and asks you to accept it. If you do, LOAD will talk only to a server showing exactly that certificate.

Check that it matches

On your computer, open the same address you gave LOAD, up to the port, such as https://nas.local:9802/, in a browser. Your browser will warn you about the certificate. That's expected. Look at the certificate's details and compare its SHA-256 fingerprint with the one on your iPhone.

  • Chrome: select the icon to the left of the address to open the site information, then open the certificate's details and find the line marked SHA-256 fingerprint.
  • Safari: from the warning page or the address bar, open the certificate, then expand its details until you see the SHA-256 fingerprint.

The two should be identical. If they are, tap Trust this certificate. If not, tap Do not trust and check that you're on your own network.

When there's no prompt

If your NAS uses a certificate from a public authority such as Let's Encrypt, iPhone already trusts it and LOAD shows no prompt. Asustor gets one in Settings → Certificate Manager, and Synology in Control Panel > Security > Certificate. Let's Encrypt checks your domain from the internet first, so this takes more setup than a self-made certificate.

If it changes later

If your NAS later shows a different certificate, LOAD stops and pauses. It shows Trusted before and Now presented side by side. It doesn't connect until you decide. A changed certificate is normal if you reset the NAS or made a new one. Compare the two fingerprints the same way before you accept.

Troubleshooting

When the test fails.

The connection test stops at the first step that fails and says what went wrong. Find your message below.

What LOAD saysWhat to check
Your NAS did not answer. Check that it is on, on the same network, and that the address is right.The NAS is on and your iPhone is on the same Wi-Fi. The address starts with https:// and has the HTTPS port, not the HTTP one. LOAD may also need your permission to use the local network in iPhone Settings.
Your NAS refused this username or password.Retype both. Use the NAS user you made, not your admin login.
Your NAS refused this account access to this folder. Check that the account may read and write in it.The user has read and write on that shared folder, and isn't denied WebDAV. On QNAP, see the WebDAV permission type.
Your NAS answered, but lumento could not read the answer.The address may point at something that isn't your WebDAV folder, or at a file. Check the port and folder name.
lumento cannot use this address.Use the full form: https://, the NAS's address, the port, then the shared folder.
The test was interrupted before it finished.Keep LOAD open and tap Connect again.
lumento could not read or write its saved settings on this iPhone.Nothing on the NAS. Unlock your iPhone and try again, and restart it if it keeps happening.
Your NAS's certificate is not the one pinned on this iPhone, and lumento kept the pin it has. Disconnect, then connect again, to trust the new certificate.Tap Disconnect in LOAD's settings, connect again, and compare the fingerprint. Disconnecting makes LOAD forget what it already copied. The copies on your NAS stay.
This NAS's certificate is no longer trusted by iPhone. If you changed it, Disconnect, then connect again.Your NAS may have moved from a public certificate to its own. Disconnect, connect again and compare the fingerprint.

Your NAS answered, but the folder in this address cannot be read.The shared folder exists, its name is spelled right, and WebDAV is on.
This folder is already served by lumento STORE — pair with it instead.STORE is installed on that folder. Open lumento on your iPhone and pair with it instead of using WebDAV.
Your NAS would not let lumento create its working folder.The user can create folders, not only read, and WebDAV isn't set to read-only.
Your NAS would not list, or clear, lumento's working folder.The user can list and delete files in the folder. Read and write rights cover this.
Your NAS would not accept a test file.The user can write in the folder, the NAS has free space, and WebDAV isn't read-only.
Your NAS would not rename the test file into place. lumento writes each file under a temporary name and renames it, so a half-written file never appears under its own name.The WebDAV server supports renaming files (MOVE). A proxy in front of the NAS may block it.
Your NAS would not accept a second test file.The user can create files in the folder.
Your NAS replaced a file it was told not to replace. lumento will not use it: a rename could overwrite one of your photos.This NAS or its WebDAV server doesn't honor "don't overwrite". Your NAS does not support partial reads, which lumento needs to check a file arrived.A proxy in front of your NAS may be removing partial reads (Range requests). Connect to the NAS directly.
Your NAS would not delete the test files.The user can delete files in the folder, and a recycle bin or read-only setting isn't getting in the way.
