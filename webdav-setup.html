Set up your NAS for Generic mode.

Generic mode lets lumento LOAD write to your NAS over WebDAV, with no lumento STORE installed. This page walks you through it, one step at a time.

Jump to: Asustor · Synology · QNAP · Another NAS · Connect from LOAD · The certificate prompt · Troubleshooting

What you need

Three things.
About 10 minutes.

  • A NAS that serves WebDAV over HTTPS. Asustor, Synology and QNAP all do. So do most others.
  • Your iPhone, with lumento LOAD installed.
  • A computer on the same network, to set the NAS up from. You'll use its browser to open the NAS's settings.

What's WebDAV?

It's a way for an app to put files on your NAS over the web. It's built into the NAS, so on most units you turn it on rather than install it. On some, like Synology, it's a small package from the NAS's own app store. HTTPS is the encrypted version, so your password never crosses your network in the clear.

Before you start

What LOAD does on your NAS, and what it never does.

You're letting an app write to your NAS. Here's exactly what it does there.

Where it works

The address you enter is the folder LOAD works in. Inside it, LOAD makes one folder, _lumento, and puts your photos in year and month folders like _lumento/2026/2026.11. Beside it, it keeps two small hidden items: .lumento-generic-archive.json, and a .lumento-generic folder holding a copy of LOAD's list of what it sent, so a reinstalled app still knows. While it writes them, a temporary hidden .part file sits beside each. Nothing else.

When you connect, LOAD also writes two tiny test files into _lumento and tries to remove them again. If the folder you chose has a recycle bin turned on, turn it off for this folder, or empty it now and then: LOAD's temporary files may collect there.

How a file lands

Each file is uploaded under a temporary .part name, then renamed to its final name in one step, with the "don't overwrite" flag. An existing file is never replaced, and a half-finished upload never shows up under a real name. The .part names start with a dot, so most file browsers hide them. The "don't overwrite" flag only works if your NAS honours it, so LOAD's connection test checks that, and LOAD refuses to use a NAS that doesn't.

What it deletes

LOAD never deletes a photo once it has passed its check. It deletes only:

  • its own leftover .part files from a failed upload,
  • its own connection-test files, and
  • in the rare case that a file it has just written fails its check, that one file, and only if it is unchanged since LOAD wrote it, checked just before the delete. Otherwise LOAD leaves it and uploads a fresh copy beside it.

Your password

LOAD accepts only an https:// address. It refuses http://, because your password would cross your network in clear. The password is kept in your iPhone's Keychain.

What Generic mode can't do. It checks each file's size and, once the file lands, reads back some blocks and compares them with the phone's copy. It doesn't check every byte, and it can't tell that the file reached the disk, which STORE does. See the comparison table for the rest.

The setup

Pick your NAS.

Find your NAS's address first. You'll need it in LOAD. Use the same name or IP address you type in your computer's browser to open the NAS's settings. If you don't know it, look in one of these places:

  • the finder app your NAS maker offers for computers (the NAS's manual or box names it);
  • your router's list of connected devices, where the NAS shows by name;
  • the NAS's own network settings, which show its IP address, such as 192.168.1.20.

Why a user just for LOAD? It's optional, but we recommend it. Then the NAS itself keeps LOAD out of everything else, whatever LOAD does.

Asustor · ADM

Asustor

Menu names are shown in [brackets], as ADM writes them.

1. Turn on WebDAV with HTTPS

In ADM, open [Services] → [WebDAV]. Deselect [WebDAV over HTTP] and select [WebDAV over HTTPS], and accept the standard port 9802. Click [Apply].

2. Make a shared folder for your photos

Open [Access Control] → [Shared Folders] and add a new shared folder, for example phone-photos. Deselect [Only accessible by administrator group users] so you can use a deprioritized user in step 3. You can leave the next screens default or set as you want.

You can use existing shares, but we don't recommend it.

3. Make a user for LOAD

Open [Access Control] → [Local Users] and add a user, for example load, with a strong password. We suggest you select [Password will not expire], for if it does expire, it will look to LOAD like a standard network error. You can leave the user in the standard users group (recommended) or create a new one. Then give it rights to your photo folder: [Read & Write] (RW).

Your address will look like https://<your NAS's address>:9802/phone-photos/. Next, connect from LOAD.

Synology · DSM

Synology

Menu names are shown in bold, as DSM writes them.

1. Install WebDAV Server and turn on HTTPS

Sign in to DSM as an administrator. Open Package Center and install WebDAV Server. Open it, go to Settings > HTTP/HTTPS, select Enable HTTPS and click Apply. The default HTTPS port is 5006. You can change it, so note the one you use.

Leave Enable Anonymous WebDAV off. LOAD signs in with a user.

2. Make a shared folder for your photos

Go to Control Panel > Shared Folder and click Create > Create Shared Folder. Give it a name such as phone-photos and pick a storage location.

3. Make a user that can use only that folder

Go to Control Panel > User & Group > User and click Create. Enter a name such as load and a strong password.

The wizard has a Join groups page and an Assign shared folders permissions page. A group the user joins can bring folder rights with it, and when a user's rights and a group's rights disagree, No access wins. So on the permissions page, give the new user Read/Write on your photo folder and No access on every other shared folder, such as homes. The Preview column shows what the user can really reach.

4. Check for a separate WebDAV permission

The same wizard has an Assign application permissions page, which controls which services the user can use. Deny beats Allow there, so don't deny this user WebDAV.

Your address will look like https://<your NAS's address>:5006/phone-photos/. Next, connect from LOAD.

QNAP · QTS

QNAP

Menu names are shown in bold, as QTS writes them.

1. Turn on WebDAV with HTTPS

Log on to QTS as an administrator. Go to Control Panel > Network & File Services > Win/MAC/NFS/WebDAV > WebDAV and select Enable WebDAV. Choose Dedicated port number, enter an HTTPS port number (any free port) and click Apply. Write that number down.

If you keep Web server port number instead, the port is the Web Server's own, and HTTPS WebDAV needs the Web Server's HTTPS switched on, as in the next step.

2. Switch on the Web Server's HTTPS

Open QTS's Web Server settings and make sure HTTPS is on. This is required if you kept Web server port number above; it does no harm with a dedicated port.

3. Make a shared folder for your photos

Open File Station, use the create button on the menu bar, and choose Shared Folder. Give it a Folder Name such as phone-photos and pick a Disk Volume.

4. Make a user that can use only that folder

Go to Control Panel > Privilege > Users, click Create > Create a User and enter a username such as load and a strong password. Under Shared Folder Permission, click Edit and give the user Read/Write on your photo folder.

Watch the default folders. QTS makes Multimedia, Public and Web folders. Any user account can use Public, with Read Only by default. Set the new user to Deny on those folders and on any other folder you don't want LOAD near.

The same window lets you edit Application Privilege. QNAP recommends denying a user the apps and network services it doesn't need. Do that, but leave WebDAV allowed.

5. Choose the WebDAV permission type

Back on the WebDAV page, QNAP offers two options: Shared folder permission and WebDAV permission. Choose Shared folder permission, so the folder rights from step 3 are the ones that count. If LOAD's connection test then says the account is refused, this is the first thing to check.

Your address will look like https://<your NAS's address>:<HTTPS port>/phone-photos/. Next, connect from LOAD.

Any other NAS

Another NAS

Menus differ, but the four steps are the same. Look in your NAS's own help for the words below.

1. Turn on WebDAV with HTTPS

Look for a WebDAV setting, in the file services or sharing section, and switch on the secure (HTTPS or SSL) version. Note the HTTPS port. It isn't 443 on every NAS.

2. Make a shared folder for your photos

Make a new shared folder only for photos, such as phone-photos.

3. Make a user that can use only that folder

Make a new user, with a strong password, that can read and write that folder and nothing else. Check any default shared folders, such as public, and deny the new user access to them.

4. Check for a separate WebDAV permission

Some NAS units also decide which users may use WebDAV at all, apart from folder rights. If yours does, allow the new user.

Then connect from LOAD. The connection test checks everything LOAD needs and tells you what's missing.

Connect from LOAD

Three boxes and a test.

In LOAD, choose Connect over WebDAV. On the Connect your NAS screen, fill in:

  • Address: https://<your NAS's address>:<HTTPS port>/<shared folder>/. The address is the name or IP address you found at the top of the setup section, such as 192.168.1.20. The examples below use <your NAS's address> as a placeholder: replace it with yours.
  • Username: the user you made.
  • Password: that user's password.

Examples

  • Asustor: https://<your NAS's address>:9802/phone-photos/
  • Synology: https://<your NAS's address>:5006/phone-photos/
  • QNAP: https://<your NAS's address>:<HTTPS port>/phone-photos/

The folder at the end of the address is where LOAD works, so a deeper folder such as …/phone-photos/iphone/ works too.

The connection test

Tap Connect. The button reads Testing… while LOAD runs its test on your NAS. It checks that the NAS speaks WebDAV, that your folder can be read, and that LOAD can write a file and rename it into place, that your NAS refuses to overwrite, and that it reports a size and lets LOAD read part of a file. It then removes its test files. Each step shows as it passes. When they all pass, you'll see Connected.

If it says your NAS uses HTTP/2: iPhones can't upload to an HTTP/2 server in the background, so LOAD copies while it's open. Keep LOAD open for the Load.

The certificate prompt

"Check this certificate."

You'll probably see this once. It's the right thing to see.

Most home NAS units make their own HTTPS certificate, so no outside authority vouches for it. The first time you connect, LOAD shows you the certificate's SHA-256 fingerprint and asks you to accept it. If you do, LOAD will talk only to a server showing exactly that certificate.

Check that it matches

On your computer, open the same address you gave LOAD, up to the port, such as https://<your NAS's address>:<HTTPS port>/, in a browser. Your browser will warn you about the certificate. That's expected. Look at the certificate's details and compare its SHA-256 fingerprint with the one on your iPhone.

  • Chrome: look for the icon to the left of the address, which opens the site information, then look for the certificate's details and the line marked SHA-256 fingerprint.
  • Safari: look for a way to view the certificate from the warning page or the address bar, then expand its details until you see the SHA-256 fingerprint.

Menu names change between browser versions.

The letters and numbers should be the same, in the same order. Ignore spaces, colons and upper or lower case. If they are, tap Trust this certificate. If not, tap Do not trust and check that you're on your own network.

When there's no prompt

If your NAS has a certificate from a public authority such as Let's Encrypt, and the address in LOAD is the domain name on that certificate, for example https://myname.synology.me:5006/phone-photos/, iPhone already trusts it and LOAD shows no prompt. If you connect by nas.local or an IP address instead, the name doesn't match the certificate, so you will see the prompt anyway. In that case don't set up Let's Encrypt for LOAD: it replaces the certificate every few months, and each renewal would pause LOAD.

Asustor offers Let's Encrypt in Settings → Certificate Manager, and Synology in Control Panel > Security > Certificate. Check your NAS's own help that WebDAV uses that certificate. Let's Encrypt checks your domain from the internet first, so this takes more setup than a self-made certificate.

If it changes later

If your NAS later shows a different certificate, LOAD stops and pauses. It shows Saved and Now presented side by side, with an Accept new certificate button. It doesn't connect until you decide. A changed certificate is normal if you reset the NAS, made a new one, or a renewed certificate arrived. Compare the two fingerprints the same way before you accept.
